# Axiom Tech Debt

Use when asked to assess "how bad is this" or triage a backlog of known issues.

## Framing
- State the concrete cost of leaving it (incidents caused, dev time lost, onboarding friction) — not just "this is messy."
- State the cost to fix, roughly, so it can be weighed against the cost of leaving it.
- Assign an owning repo/team — debt with no owner never gets scheduled.

Prioritize debt that is actively causing incidents or blocking other work over debt that is merely unaesthetic.
