# Axiom Changelog Writing

Use when preparing a release or notable PR description.

## Format
- Group by Added / Changed / Fixed / Removed.
- Write from the user's perspective ("Fixed X breaking under Y"), not the diff's perspective ("refactored internal function").
- Link the PR or issue for traceability.

Skip internal refactors with no user-visible effect — changelog is for consumers, not contributors.
